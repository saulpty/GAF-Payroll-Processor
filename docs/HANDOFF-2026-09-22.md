## What it was

The Attendance button in the top nav pointed at `/attendance`, and that route rendered
`<Navigate to="/attendance/today" replace />`. UI Bakery's workbench mirrors the running app's URL:
about 40 ms after any `replaceState` it writes its own remembered value back and fires a `popstate`.
React Router then re-rendered `/attendance`, our redirect fired again, and the two took turns.

Measured on prod, inside the app iframe, with `history.pushState` / `replaceState` patched to record
every call:

```
push     /attendance            (the nav click)
replace  /attendance/today      (our <Navigate>)
replace  /attendance            (workbench chunk-4WD2D6MM.js) → popstate → repeat
```

**448 history operations and ~250 database requests in about two seconds**, per click. It ended on
`/attendance`, which rendered the **List** tab with no tab highlighted, and the backlog of queued
queries made every page after it crawl until a hard refresh. **There was no console error** — the
only symptom was the flash and a wrong, slow page.

Two things hid it: a **full page load is fine** (the workbench has no remembered URL yet to write
back), and clicking the **Today sub-link is fine** (no redirect involved). It only reproduces on an
in-app click to a route that redirects.

## The fix (prompt `2026-09-22-today-redirect-loop/01`, six files)

A route the app navigates to must render its page, not redirect to another route.

- `Attendance.tsx` — `<Navigate>` deleted, `tabFromPath` defaults to `today`, so `/attendance` and
  `/attendance/today` both render Today.
- `TopNav.tsx` — the Attendance section's `home` is `/attendance/today`.
- `access.ts` (`homeFor`), `RequireSuper.tsx`, `UsersTab.tsx` (view-as) — all point at
  `/attendance/today`.
- `FilterBar.tsx` — explicit `/attendance/list` key so the list keeps Periods | Dates, while
  `/attendance` now carries Today's controls.

Guarded by **L7** in `tests/lessonGuards.test.ts` (no `<Navigate>` in `Attendance.tsx`, no nav home or
`homeFor` pointing at the bare `/attendance`); `AX4` in `access.test.ts` updated. Lesson written up in
`docs/LESSONS.md`.

### b. Saturday Sep 19 was simply missing (fixed + backfilled, prompt `2026-09-22-weekend-gap/02`)

Full write-up: `docs/findings/2026-09-22-weekend-sync-gap.md`. The keep-fresh sync asked for
yesterday and today only and runs solely while a super user has the Hub open, so a weekend with
nobody signed in left a permanent hole - Sep 19 had **zero rows** while Teramind held a full day for
four people. Worse, the pull log counted a capture entered on Sep 17 as covering `2026-09-11 to
2026-09-25`, eight days that had not happened, so Process Payroll would have offered Tim a "saved
copy" of Q2-Sep with a whole Saturday missing. The window is now a week and every log entry is
clamped to the day it ran. Sep 19-20 were backfilled by hand.

### c. Frozen table headers (prompt `2026-09-22-sticky-headers/01`)

Saul: *"i feel that employee and dates etc should freeze when scrolling down."* `DataTable` already
rendered its header `sticky top-0`, but its wrapper was `overflow-auto` with no height, so the card
grew to fit and the page scrolled instead — a sticky header only sticks inside the box that actually
scrolls. The two Activity tables now carry `max-h-[70vh]`, and the expanded day header is
`sticky top-[33px]` so it pins flush under the main one (measured on prod: main header 198→231, day
header top 231, gap 0). `DataTable` itself is untouched, so Contracts, PTO and Disciplinary are
unchanged — say the word if you want them to behave the same way.
