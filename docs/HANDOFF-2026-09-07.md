## 2. What the probes changed, before a line of UI was written

Three read-only probes ran first. They moved the design in five ways, and every
one of them would otherwise have been a defect on screen.

| Assumption in the spec | What the data said |
|---|---|
| ~7 actions, 5 employees | **16 actions, 10 employees, 4 managers** |
| Juan Molina is the live example | **Timothy Moore** — 4 actions, the only Second Written |
| Latest action 2026-06-30 | **2026-08-19** |
| Fall back to the form's role when the *name* fails to match | Two employees **match fine but have a NULL roster role** |
| Inactive employees are a theoretical case | **Two of the ten are inactive** |

The role one is worth dwelling on. The design said the page prefers the roster's
`role` and falls back to the disciplinary record's only when the name cannot be
resolved. **Juan Molina and Osvaldo Medina resolve perfectly well and have no
roster role at all.** Under the design as written, two of ten rows would have
shown a blank role while the record plainly said *Intake 1* and *EVV
Specialist*. The fallback now triggers on an empty roster value, independently
of matching.

Also confirmed rather than assumed: **`submitted_at` is identical to the second**
on the actions that share a `document_date`, so `id DESC` is the only thing that
can order them. Timothy Moore has **three** such actions.

And **all ten names resolve exactly** — the *"not on roster"* chip has no live
instance. It stays in, proved by unit test, because the other app can produce
one at any time. The aliases that make it work are a reminder of why the
resolver exists: *ally papatsoris*, *ozzy medina*, *menky torrano*,
*Gigi Sandoval*, *Tim Moore*.

### The page

One row per employee with a record: Employee, Manager, Actions, Highest level,
an **escalation ladder** of four dots, Latest, Status. A segmented
**All / Open / Overdue / Closed** toggle, the usual Employee/Role/Manager filter
bar, and an Excel export that flattens to one row per action.

Expanding a row opens **one line per action** — date, level, scenario, a
truncated *what happened*, manager, re-evaluation, status. Expanding one of
those lines opens that action's full detail: the six narrative fields, the
evidence and prior-warnings meta line, and either a **Close case** button or the
closure with a **Reopen** link. One action open at a time.

### 3.1 The first version was hard to read, and why

It originally printed every narrative field of every action at full length the
moment a row opened. For three actions that is eighteen paragraphs with nothing
to skim. Saul's verdict was blunt and correct.

It also opened with a header strip repeating Actions, Highest level, Escalation
and Last action — **all four already visible in the collapsed row one line
above**. The reader paid for that duplication before reaching anything new. The
strip is gone and `CaseFile.tsx` went from 11.8 KB to 5.9 KB.

### The acceptance case

**Juan Molina**, now that Timothy's records are gone. Three actions, ladder to
First Written, inactive so the row is muted, and a job title that survives only
because the fallback reads it from the disciplinary record.

His file renders **06-16 Calls → 06-16 Attendance → 06-23 First Written**. The
two 06-16 rows share a `document_date` **and** an identical `submitted_at`, so
that ordering is reachable only through the `id` tiebreak. **If they ever appear
in another order, the tiebreak has been lost.**

Timothy Moore was the original acceptance case and was better — four actions, a
Second Written, and a *latest* one rung below his *highest*. That combination no
longer exists in the data.

### The write path, tested in both directions

Tested before the test rows were deleted, on one of Timothy's actions. The
header went **16 open → 15 open** — which is `06b`'s `onChanged={reload}` doing
its job — the footer showed *Closed 09-07-2026 by Saul Fallenbaum*, and a Reopen
link appeared. **Reopen restored it exactly**: back to 16 open, all four Close
case buttons returned, no trace left in the database. Both readings come from a
re-query, not from local state.

## 5. Three things learned about driving UI Bakery

All three are now in `LESSONS.md`.

**Clicking submit during a run interrupts it — it does not queue.** A prompt sent
while the previous round was still working stopped that round, was never
delivered, and left its text in the textarea so the next paste doubled it. The
length check caught it at 18 436 characters against a 9 218-character file.
**Check `.value.length` before every submit, not just the first.**

**An offer to "build the whole thing" must be declined by silence.** After the
actions round, UI Bakery asked whether to build the full page — and then started
doing it unprompted, editing `TopNav.tsx` and `FilterBar.tsx`. Nothing reached
the export, but only because the run was interrupted. Send the next numbered
prompt instead of answering, and sync afterwards to confirm nothing was left
behind.

**`::text` does not stop Postgres handing back timestamps.** The driver
re-serializes the cast, so `document_date::text` still arrives as
`2026-06-24T00:00:00.000Z`. `LESSONS.md` already carried the symptom; it now
carries the mechanism and the sharp edge — `'2026-10-07T00:00:00.000Z' <=
'2026-10-07'` is **false**, so an unsliced `<=` silently drops the boundary day.

## 6. One test was wrong, and it was worth fixing properly

`D9` and `D9b` scan `disciplinary.ts` for `new Date(` and `Date.now()`. Both
failed — on the module's own **comments**, which say it avoids exactly those
calls. There is no such call in the code.

Making them pass by deleting the comments would have been backwards, so the
guard was fixed instead: `stripComments()` runs first, `D9` additionally asserts
`Date.UTC(` survives stripping so it cannot pass vacuously, and **`D9c` is new** —
it guards the guard with one commented and one real `new Date()`, asserting
exactly one survives.

`tenure.ts`'s `T7`/`T7b` share the weakness but pass today, so they were left
alone.

## 8. Deliberately not built

- **Creating or editing an action.** The form app owns authorship.
- **PDF download.** Saul chose text detail. The two `pdf_*_base64` columns are
  never selected — one row is ~250 KB, and `SELECT *` would move a megabyte for
  sixteen rows.
- **Manager-scoped visibility** (G). `loadDisciplinaryActions` takes `manager`
  from day one, so it stays a wiring job.
- **Backfilling closures** for cases already closed by email.
- **A live-updating nav badge.** It reads once when `TopNav` mounts, so closing a
  case updates the table immediately but the badge only on the next load. Same
  as the Contracts badge.
