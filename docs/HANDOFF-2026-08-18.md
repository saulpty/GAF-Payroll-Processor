## Facts worth not rediscovering

- **Monday mirror/lookup columns return `text: null`.** The value is in
  `display_value`, which needs `... on MirrorValue { display_value }` in the
  query. Reading `.text` yields blanks with no error.
  See `docs/findings/2026-08-18-monday-column-map.md`.
- **Board 8592460836 is the Panama Employee Directory; 8661565945 is Employee
  Onboarding.** A past migration confused them.
- **`text_mkzj84w1` is Manager; `text_mkzj8b73` is Manager Email.** Both valid,
  which is why using the wrong one failed silently.
- **The Onboarding board has no email column,** so its rows match by name only.
  That is why eight active employees needed legal-name aliases.
- **UIB's agent sandbox cannot POST.** Only the browser runtime can call a
  Monday action. To query Monday ad hoc, use the API playground at
  `vitasya-hc.monday.com/apps/playground` — it uses your logged-in session and
  needs no token.
- **UIB is idle when the chat box reads "Ask UI Bakery…"** and busy when it
  reads "Working on your request…". The send button keeps its class either way,
  so it is not a reliable signal — exporting on that basis gives an empty diff.
- **`src/task.md` moves on larger tasks.** It is UIB's own scratchpad, not app
  code. Harmless, but it will keep appearing in diffs.
- **Repeated tab freezes and "Unknown error" on several actions at once mean
  infrastructure, not code.** Close extra app tabs and retry before suspecting
  the change.
