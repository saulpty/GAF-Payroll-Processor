# Handoff — 2026-09-11, Payroll Master save bugs

Saul's four reports from editing Q1-Jun-2026 rows, traced and fixed in seven
prompts on `/dev`, merged to `main`. **Not released** — Saul releases.
Findings: `docs/findings/2026-09-11-payroll-master-save-bugs.md`. Prompts:
`docs/superpowers/prompts/2026-09-11-payroll-save-bugs/` (01–07 sent; 08
written up in the plan but **not sent** — it touches the engine and needs
Saul's explicit go).

## What was wrong, in one line each

1. **Save button never went away** — the page kept its scratch copy of the
   row after saving, and "is there a scratch copy?" was the dirty test.
2. **Late/Early minutes never recomputed** when Entry/Exit changed — only the
   two time strings were written; discount and status derived from stale
   minutes. Same on Action Required.
3. **No way to discard an edit** except leaving the page.
4. **Luis Abad 6/1's 985 early minutes** — a Teramind session that crossed
   midnight; the engine read the next-day exit as 00:35. The stored
   `"12:35am"` came from a `TimeInput` crash on that spelling.

Carlos Aloma 2026-06-03 (late/early 0, notes unchanged).

## Blast radius checked

Only the engine's upsert wrote the minute columns before; no trigger, view or
snapshot recomputes or compares them. Attendance List/Reports, HRK Summary
and Period Log read the stored minutes, so they now show corrected numbers
after an edit. Unchanged and worth knowing: blanking `entry_time` drops the
day from the Attendance dashboard; a payroll **re-run overwrites every
column** including operator-corrected punches (`upsertPayrollEntries`, no
guard).

## Not done / open

  in the plan and not sent. Without it the *next* payroll run will again

  `useBlocker` needs a data router and `app.tsx` uses `BrowserRouter`. The

  Both remain on the high-blast-radius list.

## Things that went wrong on the way

- The builder renderer froze on four of seven rounds (`Runtime.evaluate timed
  out`); one-shot checks after a 10 s wait always recovered it.
- Heredocs with `\d` inside Bash ate the backslashes and produced a broken
  regex in a prompt; caught by dry-running the tests against a scratch copy
  of the helper before sending. Do that for every pure module.
- `node --test` cannot resolve an extension-less `./classificationEngine`
  import, so `punchMinutes.ts` carries its own six-line time parser instead
  of importing the engine's.
- A React row reference goes stale across `reload()`; every browser check
  re-queries the row by employee + date.
- Nit from prompt 07: in the commit-confirm list UIB wrote
  `edit.event_type_1 || row.event_type_1` where the old code had `??`, so a
  row whose event was deliberately cleared shows the old event in that
  preview list only. Display-only; the commit itself writes the cleared value.
