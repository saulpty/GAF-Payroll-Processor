## What changed

1. **Pending → Review.** The column, the header count and the "Only with
   review" filter count only requests that can be recorded *now*: return date
   passed **and** payroll processed through it. Everything else shows as a
   muted "N not yet" beside the chip. Requests whose return is before their
   leave are never counted.
2. **Nav badge** on the PTO Tracker tab with the global review count; it
   refreshes when a request is recorded, restored or withdrawn (new
   `ptoVersion` signal in `GlobalFilterContext`, which also fixes the stale
   `periodsVersion` memo dependency).
3. **Pay impact next to every event** in the In-payroll cell and the dialog
   panel: `Ausencia Justificada. ×1 · Incapacidad`. Same event with two
   impacts stays two lines.
4. **Record waits for payroll.** `recordability()` in `ptoPayrollMatch.ts` is
   the one rule: invalid dates → future → payroll not processed → ok. The row
   button, the record-mode dialog and the SQL counts all use it. Edit and Add
   manually keep only the "return date has passed" rule so pre-March rows stay
   editable.
5. **Broken requests are flagged in the row**: red chip *Return is before
   leave — fix on Monday*, Record disabled with *dates don't make sense*.
6. **Refresh in place.** Withdraw / Restore / Record / Edit no longer unmount
   the table; the expanded employee and the scroll position survive.
7. **Wider sub-table**: the Source column folded under the Status chip;
   In-payroll gets the room.
8. **Period-name guard** (Saul's explicit OK to touch `ProcessPayroll.tsx`):
   the name is trimmed, must look like `Q1-Aug-2026`, and a near-miss of an
   existing period is refused with the look-alike named. Plus a `NOT VALID`
   CHECK on `periods.period_name` so a bad name fails even if the UI is
   bypassed; the two legacy free-text names stay.
