## What changed on the PTO tracker

Saul spent a day comparing every PTO request against Payroll Master by hand and
sent six pieces of feedback. Each maps to one change:

1. **Withdraw is no longer a disappearance.** Withdrawn rows stay in the
   employee's breakdown, dimmed and struck through, with a **Restore** button.
   The "Show withdrawn" checkbox is gone. A withdrawn row keeps its Monday link,
   so the request no longer bounces back as Pending — Restore, then Edit, is the
   way to re-record. Pending counts dropped for anyone who had a withdrawn row.
2. **The payroll cycle is named.** The "In payroll" column shows the cycle(s)
   the days landed in (`Q1-Apr-2026, Q2-Apr-2026`).
3. **Nothing can be recorded before it has happened.** Record on a pending row
   is disabled with "in N days" until the return date has passed; the dialog
   refuses a future return date in all three modes (record, edit, manual).
4. **What actually happened replaces Comments.** For every request: the off
   days payroll recorded (`PTO ×3, Feriado ×1`), the first day off, the day the
   person was actually back (first punched day), and the day count — calendar
   days for PTO (weekends count), off-row count for floating holidays. Green
   check when it matches the request, amber `⚠ 3 days, not 4` when it doesn't.
   A request whose cycle hasn't run reads *Not processed yet · payroll runs
   through Mon Aug 24*; one that hasn't started reads *Future*. Comments live in
   the row tooltip and the dialog. The dialog shows **Requested vs In payroll**
   side by side with a **Use payroll dates** button.
5. **FH left counts days, not records.** Charles Bush recorded two floating
   holidays as one row and saw "FH left 1"; `fh_used` was `count(*)`. It is now
   `SUM(total_days)`, and for 2026 it is never below what the August spreadsheet
   said (`GREATEST`). Hover the FH-left value to see both numbers. Floating
   holidays never count weekends: the dialog auto-fills weekday count for FH,
   calendar span for PTO.
6. **Employee search suggests names** as you type, on every page that has the
   box (PTO, Attendance, Payroll Master, Contracts, Disciplinary, Summary,
   Action Required). Arrow keys + Enter pick; picking writes the exact name, so
   every page's existing filter works unchanged.

Dates on the PTO page now read `Mon Aug 17 → Fri Aug 21`, with the year only
when it isn't the current one. Other pages keep `MM-DD-YYYY` for now.

## How "actual" is decided (`src/app/lib/ptoPayrollMatch.ts`)

- A day **off** is a payroll row with no clock-in whose event type is PTO /
  Permiso Remunerado / Feriado (for a floating holiday: the row whose pay
  impact is `Floating Holiday / B-Day Off`).
- The **return** is the first punched row after the first day off that is not
  a leave type. A punched PTO day is "worked during leave", not a return.
- **PTO days** = calendar days from first day off to the return. **FH days** =
  number of off rows. Days nobody works produce no payroll row, which is why
  PTO counts by span, not by rows.
- Back-to-back requests are bounded by the next request's leave date.
- Someone with no rows at all is neutral (`No payroll rows`), never flagged.

## Things that went wrong on the way

- **The action runtime rejects arithmetic on a parameter.** Round 02 shipped
  `LEFT(work_date,10) >= (({{params.year}}::int - 1)::text || '-12-01')` and
  every breakdown failed with `Can't execute loadPtoEmployeeDetail action:
  Unknown error` — the SQL runs fine by hand. Deterministic on Retry, so a
  defect, not a blip. Fix (02b): compute `daysFrom` in the browser and pass it
  flat. Rule for next time: **a `{{params.x}}` is a value, never an operand.**
- **Export keeps re-adding a line to migration `1781995000`.** Every export
  since 38 appends the old one-line rollback note under the block prompt H
  wrote yesterday. Comment only, no SQL. Committed as exported rather than
  fought a third time; the block above it still says the right thing.
- The ⋮ → Export menu needs a hover first and often does not open on the first
  click after a navigation. Zoom on the sidebar before clicking Export — the
  Export coordinate lands on another app's row when the menu is closed.

## Known limits (said once, not hidden)

- **Actual return = first punched non-leave row.** A mid-leave day the engine
  did not classify as PTO reads as an early return. The ⚠ plus the tooltip
  listing every row type is the tell.
- **Weekend-inclusive PTO.** A Friday-only PTO whose Monday request says
  "return Saturday, 1 day" is flagged and *Use payroll dates* writes 3 days.
  That is the spreadsheet's convention and Saul's rule.
- **`GREATEST(sheet, recorded)` can under-count** when the sheet says 1 and a
  *different* FH is later recorded. Clean fix is in BACKLOG item J: backfill
  the sheet's 2026 floating holidays as dated rows, then drop the GREATEST.
- The today guard uses real today, not the As-of picker.
