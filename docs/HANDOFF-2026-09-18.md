## What is deliberately NOT done

- **Server-side auto-sync.** `MondayAutoSync` only runs while a super user has the Hub open in a
  visible browser tab. Data pulled at 7 am with nobody logged in stays stale until someone opens the
  app. A true server-side timer needs a **UI Bakery Automation**, configured in the UIB platform UI
  outside this repo — and Saul's account cannot see the Automations project; it belongs to the VP.
  (Was already open from 09-17 for Teramind alone; now applies to the combined sync too — BACKLOG #15.)
- **Activity Charts tab** (slice 6 of the plan) — not started.
- **Help / methodology copy** explaining Active Time, Needs A Look, etc. to Saul or Tim (slice 8) —
  not written.
- **Threshold tuning.** `activity_min_active_minutes` is seeded at 390 (a 6.5 h floor on an 8 h
  shift). Run against real Q1-Sep data it flags **203 of 523 days** as Needs A Look — almost 40%,
  clearly too sensitive as a first cut. Suggest lowering to 360 (6 h) but this is Saul's call, not
  ours; nothing was changed.
- **The UIB Automation for the Teramind pull itself** (mentioned in 09-17's handoff) is still open,
  now folded into the same VP-owned Automations blocker above.
- Silent employee creation from `MondayAutoSync` (new hires appear without an "Add unmatched
  employee?" confirmation, unlike the old manual sync) was a deliberate scope decision for
  auto-running code — a background process cannot pop a dialog — but it means a Monday board typo or
  test row could silently create a phantom employee. Worth a second look before release.

## What went wrong along the way, and how the loop caught it

- **PowerShell encoding, twice.** `Get-Content`/`Set-Content` and `-Raw` without an explicit UTF-8
  encoding double-encoded `·` and `—` in two different docs mid-session. Caught by re-reading the
  file after writing it and seeing mojibake; fixed by using `[System.IO.File]::ReadAllText` /
  `WriteAllText` with `UTF8Encoding($false)` instead of PowerShell's own cmdlets.
- **UIB split files nobody asked it to split.** Two prompts came back with an unrequested file split
  (FilterBar → +AttendanceRangeControls, employee panel → frame + body + days) to stay under the
  15 KB rule. Accepted both — they solve exactly the problem the rule exists for — then committed
  with a message noting the collateral file.
- **A chip kind got hidden that the prompt wanted shown.** Prompt 01 asked for a `No Reports Yet`
  amber chip; the first round rendered nothing for that case instead (UIB read "no chip" from an
  earlier "no flag" instruction and over-applied it). Caught only because the acceptance criterion
  named the exact visible outcome ("Navvad and Timothy show No Reports Yet") rather than "the Why
  column works" — fixed in prompt 01b.
- **`/dev` 500s during a UIB redeploy.** For roughly 1–2 minutes after any prompt finishes, `/dev`
  returns 500 "Unknown error" on every DB call while UIB redeploys the draft. Judged the page as
  broken once before recognizing the window; now every verification step waits it out and reloads
  before concluding anything.
- **`document.hidden` blocks testing in the obvious way.** Because the auto-sync gate is
  `document.hidden`, simply switching to another window (which is what "in the background" means to
  a human) makes Chrome report the tab hidden and the sync correctly refuses to run — which looks
  identical to a bug. Verified instead by overriding `document.hidden` directly on the iframe's
  document from the console.
- **A closed Chrome tab group kills the AI-panel tab**, but the round itself keeps running
  server-side — reopening the tab group and re-installing the loader script picked the same run back
  up mid-stream rather than losing it.
